1. Challenge Overview & Task Objectives

The ML-Arena Challenge 194 requires building an autonomous data science agent capable of answering diverse quantitative tasks. Each task consists of an English objective, optionally accompanied by CSV data files and a data dictionary. The required output is a single number, evaluated within a tolerance of 1.5 × 10−n for n requested decimal places.

2. Task Taxonomy & Execution Constraints

The private evaluation set consists of 120 unseen tasks. The system runs under strict constraints: a local model of about 1.5 billion parameters (Qwen2.5-Coder-1.5B), no internet access, 3 vCPUs, 3 GiB of RAM, and 40 seconds per call of 8 tasks.

3. Overall System Architecture

Version history in brief. Ten versions were submitted to the private leaderboard, in three phases (full table in section 7): phase 1, v1, the LLM writes the code for every task (51.7 %); phase 2, v2 to v5, deterministic rules first with the LLM as a fallback (74.2 → 92.5 %, file stage3.py); phase 3, v6 to v10 (5–6 November 2026), wider rule coverage and cross-checked rules (93.3 → 97.5 %, file agent_v10.py). In this report, "the v5 rules" are the rules written in phase 2 and kept unchanged in the final agent; "the corrected rules" are an independent rule set written in phase 3 (v5b) and corrected from v7 to v10.

DS-Harness is a two-tier design: high-precision rule solvers first, backed by an LLM code-generation pipeline with error recovery, answer checks and voting.

4. Deterministic Rule Engine (Rule-First Strategy)

The rules exploit the regularity of the task generator. A rule answers only when the whole question matches its template; otherwise it abstains and the task goes to the LLM.

  • Fits (25/25 private): target = the train.csv column missing from test.csv; features matched to the dictionary; year filters; unregularised linear or logistic regression; predictions, intercepts, coefficients, odds ratios, R², counts and mean predictions.
  • Tables (48/50 private): narrow templates for types absent from dev (share of a total, days between dates, gaps between groups, top-k, mode, interquartile range, weekday and quarter filters, date ranges, negations, A or B, per-group spread and distinct counts, weighted means, year-over-year change); the original v5 rules for statistics, filters, groups, joins and derived columns; a corrected rule set that cross-checks them.
  • No files (44/45 private): the v5 templates plus about 130 further templates in three waves (dates and times, logarithms and powers, compound, simple, monthly and continuous interest, half-life, divisors, primes, binomial and hypergeometric probability, variance, mode, unit and temperature conversions, mixtures…).
Two rule sets, cross-checked (v10) The v5 table rules are kept verbatim. A second, corrected implementation runs on the same task; when both answer and disagree, the corrected answer is kept. On generated tasks the corrected rules were right in 41 of 41 disagreements; on the private set this step added two table tasks (46 → 48).
Wrong rules are worse than abstentions On generated tasks of types absent from dev, the v5 rules answered 50 of 420 tasks wrongly instead of abstaining (an interquartile range computed as max − min, "number of distinct carriers per depot" counted as rows, "not of the Lyon store" read as "of the Lyon store"). A wrong rule hides the task from the LLM. v10 vetoes these constructs and solves them with dedicated templates.

5. LLM Fallback & Self-Correction Pipeline

For tasks outside the rule scope, Qwen2.5-Coder-1.5B writes executable Python:

  • Compact prompting: cleaned table schemas, dictionary, instructions and one worked example.
  • Parser hints (v9): what the parser understood even when no rule answered — the resolved column of the measure, the grouping column, the filters, and, for proportions, the population and the counted rows kept apart.
  • SmartFrame and repair: column-name mismatches are recovered at run time; failed code is sent back with its error message; truncated code is continued.
  • Answer checks (v8): candidates that break the form the question asks for (a fraction or probability outside [0, 1], a non-integer count, an invalid date, a rank below 1) are discarded before the vote. None of the true answers of 9,811 tasks is rejected.
  • Weighted vote: greedy result weight 1.5, each sample weight 1; 8 samples instead of 4 when four tasks or fewer of a batch reach the model (v9); internal budget of 29 s, every generation bounded by max_time.

8. Testing Methodology

The dev set was used to write the rules, so it cannot measure generalisation. Changes were therefore tested on data built for that purpose, and the LLM path, which could not be run offline, was measured only through the private score.

  • Generators with ground truth: the seven table domains, the five fit domains and the nine no-file categories are rebuilt with dev's formatting traps (separators, decimal commas, missing-value tokens, units in cells, -1 sentinels, duplicates, day-first dates, key prefixes). The truth is computed on the clean data, independently of the agent.
  • Paraphrases of dev: real dev objectives rewritten without changing their meaning (operator synonyms, filler sentences, sentence order, rounding phrases, "Find" instead of "What is").
  • Strict non-regression: every version is compared task by task with the previous one, with a stub LLM, on answers and on the exact prompts sent to the model.

9. Failure Analysis & Lessons

Three of 120 private tasks are still missed: two tables and one no-file task. Their scores did not move with any change of the LLM path, so they are most likely decided by rules; task-level private errors are not available.

  • Stable scores are a diagnosis. Five LLM-side variants gave exactly the same family scores, which pointed to deterministic errors; cross-checking two rule implementations then recovered two tasks.
  • Generated data is a safety net, not the arbiter. Extending the corrected rules to tasks the v5 rules abstain on looked better on generated data but cost five private tasks: the LLM with hints handles unseen phrasings better than generic rules.
  • Leaderboard selection. v6–v10 were chosen among about a dozen submissions on the same private set. Each was a single explained hypothesis, but the final score also reflects that selection.
  • Next step. Measure the LLM path offline with the rules switched off (DSH_RULES_OFF) on a GPU, then target the forms where the model fails.
