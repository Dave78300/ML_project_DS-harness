[ SYS.03 // RATIONALE DE DESIGN ]

Pourquoi la Stratégie Rule-First ?

LIMITES Problèmes du pur-LLM 1.5B
  • Hallucinations fréquentes sur les calculs exacts
  • Erreurs de syntaxe Python sous pression
  • Latence élevée sur CPU, budget de 5 s par tâche
  • Notre v1 (LLM seul) : 51.7 % au privé ; référence du challenge : 53.3 % sur le dev
VERSUS
→
AVANTAGES Atouts de DS-Harness
  • Réponse exacte dès qu'un gabarit est reconnu
  • Exécution en quelques millisecondes
  • Budget temps préservé pour les cas ouverts
  • Une règle s'abstient si elle n'est pas sûre
Leçon de la phase 3 : une règle fausse est pire qu'une abstention. Le LLM rattrape une abstention, jamais une règle qui se trompe.
Démarche suivie à chaque jalon
1 · Diagnostiquer
Familles et formulations qui échouent
›
2 · Une hypothèse
Un changement principal à la fois
›
3 · Vérifier hors ligne
Dev, tâches générées, non-régression
›
4 · Le privé tranche
La meilleure variante devient le jalon

[ SYS.07 // FALLBACK & AUTOCORRECTION ]

Supervision du LLM Qwen2.5-Coder

PROMPTING
Contexte réduit + indices
  • Modèle Qwen2.5-Coder-1.5B
  • Schéma exact, dictionnaire, un exemple guidé
  • Indices du parseur : colonnes résolues, population et lignes comptées d'une proportion, filtres
EXÉCUTION
Boucle auto-correctrice
  • Thread surveillé, max_time sur chaque génération
  • Réparation à partir du traceback
  • Vote pondéré : glouton 1.5, échantillon 1.0
  • 8 échantillons quand ≤ 4 tâches du lot restent ouvertes
CONTRÔLES
Forme de la réponse
  • Fraction, probabilité dans [0, 1]
  • Comptage entier, rang ≥ 1, jour 1–7
  • Date YYYYMMDD valide, dispersion ≥ 0
  • Jamais appliqué aux réponses des règles
Effet mesuré au privé
Indices + 8 échantillons, v8 → v9 : tables 88 % → 92 % (94.2 → 95.8 %)
Sécurité des contrôles
0 vraie réponse rejetée sur 9 811 tâches générées
